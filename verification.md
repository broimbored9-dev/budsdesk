# BudsDesk Dafny verification

15 October 2026. Four implementation agents and an independent integration review extended BudsDesk with a Dafny-generated executable core. Source and a separately built release are included in this folder. The existing installation, shortcuts, running helper, earbud preferences and system APO deployment were not changed during this work.

## What is verified

| Module | Executed verified behavior |
|---|---|
| Protocol | CRC implementation agrees with its bit recurrence; packet header/length/CRC and command/op/payload round-trip; parser termination, valid accepted frames, residual input below 265 bytes, exact single-packet round-trip; hex acceptance/decoding; battery record selection and gesture matching. |
| Validation | Preferences and ANC restore guards; writable command whitelist and payload rules; custom EQ layout and binary32 encoding limits; sound-profile validation and exact safe payload construction for all six writes. |
| State | Operation rollover, query/response mapping, acknowledgement checks, preference/cooldown policy, pending-job overflow/underflow protection, UI control/status/draft decisions. |
| Spatial | Binary32 finite/range decisions; GUID and plugin-path guards; bounded aligned control offsets; even sequence updates, snapshot equality and heartbeat comparisons. |
| Boundary | Registry preference normalization, single-line/size limits, bounded read allowances, valid transfer lengths and response-size acceptance. |

The Rust application calls these functions through source/src/verified.rs. The implementation is generated by Dafny rather than a separate model maintained beside equivalent handwritten Rust. The five modules are included by source/verification/BudsDesk.dfy.

## Verification and builds

The combined Dafny 4.11.0 run completed with **95 verified, 0 errors**. These are verifier units, not a coverage percentage. No unchecked assumptions, axioms, extern contracts, disabled verification, skipped verification or allowed warnings are used in the project proof sources.

Normal builds reverify all included sources, regenerate into a separate work directory, compare the emitted Rust/runtime byte for byte, reject unexpected files, and validate the small generated-crate manifest. The tool download is version/checksum pinned; Cargo.lock pins dependencies. Regeneration requires an explicit -Regenerate flag and still verifies the sources. See [verification guide](source/verification/README.md).

## Fixes discovered during verification

- Reject malformed query IDs before Bluetooth writes, avoiding unsigned subtraction underflow.
- Reject invalid ANC lock strengths before producing restoration commands.
- Reject impossible helper I/O byte counts before Rust slicing.
- Reject pending-job overflow before queueing a UI command.
- Replace a signed native beat-analysis sample counter that could overflow after roughly 37 hours with a bounded counter. Its arithmetic model is Dafny-checked; exhaustive native checks cover all 561 reachable states and a 100,000-sample cadence comparison. The native helper is a tested hand translation, not generated code.
- Hex input now requires actual hex digits; the earlier Rust parser also accepted a leading plus in a two-character byte such as +0.

## Remaining boundaries

This is not a proof of the entire application. Rust conversion glue, complete worker/UI transitions, Windows APIs and unsafe FFI, memory mapping and concurrent atomic ordering, clocks, scheduling and liveness, filesystem/registry/config writes, Bluetooth hardware and firmware, dependencies, compiler and Dafny runtime remain trusted or tested boundaries. A snapshot comparison proof does not establish concurrent snapshot coherence or freedom from wraparound/ABA effects.

Float validation is proved over binary32 encodings and checked against native Rust float comparisons. The native DSP, HRTF implementation, tempo estimation, numerical stability and output bounds for arbitrary extreme floating-point input are not formally verified. Native output tests cover their specified audio fixtures. Parser tests cover representative fragmentation/corruption and every payload length; arbitrary-stream chunking equivalence is not a theorem.

No live Bluetooth, profile, ringing, audio-route or elevated APO installation changes were made for testing this release. Historical live-test reports in this folder describe earlier versions. Launching this release normally retains the application's existing behavior of starting its helper and restoring saved preferences.
